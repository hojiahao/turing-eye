日期：2026-09-19。分支：`feat/r2-scoring-rules`，基于 R1 提交 `0d05827`。代码提交：`416fc2ac86bb55302b312666a220f94c007c86a9`。规则实现、独立代码审查及 Staging 隔离回归完成，54 项 Rust 测试全部通过。三个远端分支与 PR #2 已交付，两个 GitHub 仓库的 push/PR CI 均成功；Gitea CI 尚未核实，未合并或部署业务接口。

## 本批范围

- 新增 `server/crates/review` 纯业务模块，校验平台 N 维数量、顺序、稳定键、名称和显式比例，不提供默认维度或权重。
- 比例以整数万分位保存，分数以百分之一分保存。JSON 数字精确解析，拒绝越界和超精度输入，不先转浮点再四舍五入。
- 计算 AI 维度分、AI 渠道分、两路维度分和汇总总分，中间值精确保留，公开值最终使用 HALF_UP 两位舍入。
- 区分真实零分、等待、不可用和不参与。缺必需项时保留其余有效分及具体原因，不缩小分母；零权重缺项不阻断。
- 结论只采用显式提供的合法阈值。文案、报告和外部 I/O 不进入计分模块。

现有请求字段不变。R1 中三个仅能验证结构的业务无效样例，现在实际执行权重和重复维度校验。尚未实现 HTTP handler、数据库保存、完整人工提交、Planner 生成或报告发布。
